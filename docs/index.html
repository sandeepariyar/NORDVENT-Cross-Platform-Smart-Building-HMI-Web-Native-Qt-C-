02 / Design system
A consistent language across renderers.
Fixed-screen clarity, structured controls, coherent visual states, reusable graphic resources and animation that communicates equipment behavior.


VISUAL FOUNDATIONS
Instrument-grade clarity
Dark architectural surfaces, restrained cyan operational accent and warm lighting cues. Status must remain readable at 800 × 480.


COMPONENT SYSTEM
Semantic controls
Room selection, target temperatures, ventilation mode, blinds, lighting and safety status. Values should be live text, not baked into imagery.


MOTION PRINCIPLES
Meaningful animation
Independent fan rotor, repeatable blind slats and flow dots following their exact duct paths. Reduced-motion behavior remains a design requirement.


03 / System architecture
UI engineering backed by C++.
The desktop port has a Qt-independent C++17 controller and a QML integration layer. A single shared backend for web and Qt is a future architecture goal, not a current claim.

04 / Engineering case study
From visual prototype to native HMI.
The task: retain an architectural, room-based interaction model while rebuilding the interface using a different rendering technology and moving stateful behavior toward portable control logic.


DESIGN CHALLENGE
Clarity in 800 × 480
Use room-focus camera behavior, lighting overlays and concise control panels rather than a conventional dashboard full of disconnected widgets.


IMPLEMENTATION
Two independent versions
HTML v17 demonstrates browser interaction. Native Qt v17.1 reconstructs the design using QML components, timed sequences and a C++ core.


ENGINEERING LESSON
Behavior over appearance
Animation fidelity requires alignment to actual duct geometry, individual fan rotation and physically plausible blind movement. Real hardware needs verified feedback and independent safety systems.
